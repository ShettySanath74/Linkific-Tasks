# Day 20 — Synthetic Data Generation with Faker

## Overview

This project generates realistic-looking synthetic data using Python and the Faker library. It creates related e-commerce, HR, and financial datasets, along with a large CSV dataset for testing and data-processing practice.

All generated data is synthetic and intended for development, testing, and learning. It does not represent real people, companies, accounts, or transactions.

## Learning Objectives

- Generate realistic synthetic test data using Faker.
- Use Faker providers for names, emails, dates, addresses, and company names.
- Generate structured records in JSON and CSV formats.
- Maintain relationships between related datasets.
- Apply basic data validation and logical constraints.
- Generate and validate a dataset containing 100,000 records.

## Requirements

- Python 3.10 or newer
- Faker

Install Faker:

```powershell
python -m pip install Faker
```

## Datasets

### 1. E-commerce dataset

| File | Description | Expected records |
|---|---|---:|
| `customers.json` | Customer details such as name, email, and city | 100 |
| `products.json` | Product names, categories, and prices | 30 |
| `orders.json` | Orders associated with customers | 500 |
| `order_items.json` | Products and quantities associated with orders | 1,001 |

The order records reference existing customer IDs. Each order item references an existing order ID and product ID.

### 2. HR dataset

| File | Description | Expected records |
|---|---|---:|
| `employees.json` | Employee details, department, job title, hire date, salary, and manager ID | 200 |

An employee's manager ID is either empty or references an employee in the same dataset.

### 3. Financial dataset

| File | Description | Expected records |
|---|---|---:|
| `financial_transactions.json` | Synthetic transaction details, including account ID, date, type, amount, currency, merchant, and status | 1,000 |
| `financial_transactions_100k.csv` | Large synthetic transaction dataset for testing and processing | 100,000 |

The generated transaction amounts are positive values.

## Generate the Datasets

Open a terminal in the `Day 20` directory and run the scripts in this order:

```powershell
python scripts/01_generate_customers.py
python scripts/02_generate_ecommerce.py
python scripts/03_generate_order_items.py
python scripts/04_generate_hr.py
python scripts/05_generate_financial.py
python scripts/06_generate_large_dataset.py
```

The e-commerce generation script creates customers, products, and orders. The order-items script uses those generated files to create valid order and product references.

The large dataset script writes 100,000 transaction records to a CSV file in the `outputs` directory.

## Validate the Datasets

After generating the datasets, run:

```powershell
python scripts/07_validate_datasets.py
```

The validation script checks:

- Every order references an existing customer.
- Every order item references an existing order and product.
- Employee manager references are valid or empty.
- Financial transaction amounts are positive.
- The large CSV contains exactly 100,000 data records.

A successful run prints the dataset counts and a validation confirmation.

## Expected Output

After running all generation scripts, the project should contain:

- 100 customers
- 30 products
- 500 orders
- 1,001 order items
- 200 employees
- 1,000 financial transactions
- 100,000 records in the large financial transactions CSV

## Notes and Limitations

- All data is synthetic and is intended for development, testing, and learning.
- Faker generates realistic-looking sample values; it does not verify that generated names, emails, companies, or transactions exist in the real world.
- The current scripts generate local JSON and CSV files.
- Database loading, bulk insertion, and index creation are not implemented in the current scripts.
- The `tests` directory is reserved for additional automated tests.

## Conclusion

This project demonstrates how to use Faker and Python to generate structured synthetic datasets, maintain basic relationships between records, create a large CSV dataset, and validate the generated data.
